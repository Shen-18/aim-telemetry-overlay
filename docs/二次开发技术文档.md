## 1. 项目定位与总体架构

本项目把 AiM 遥测 CSV 渲染成**带 alpha 通道的透明 HUD 视频**（MOV），叠加在赛道录像上播放。
纯 Python + Pillow 绘制、FFmpeg 编码，无 GPU 依赖，可在任何能装 requirements.txt 的机器上跑。

```
AiM CSV ──► telemetry.py（数据层）          widgets.py（渲染层）        dashboard.py（编排）
             │ 解析/列匹配/插值/对齐          │ 控件框架 + 17 种控件       │ CLI: inspect/render/verify
             ▼                              ▼                          ▼
          numpy 逐帧数组 ───────────►  RenderContext ──► frame(i) RGBA ──► render_mp.py 并行渲染
                                                                      ──► FFmpeg QTRLE/ProRes4444
                                                                      ──► verify() 逐点校验 alpha
```

三条铁律（改代码前先记住）：

1. **渲染层与数据层解耦**：`widgets.py` 只通过 `RenderContext.get(key, i)` 取数，不知道 CSV 长什么样；`telemetry.py` 不知道任何 UI。
2. **一切布局都是控件 spec 列表**：`{"type": "...", "x": ..., "origin": ..., ...参数}`。将来软件里"自由摆放控件"，序列化产物就是这份 spec。
3. **所有坐标以 1920×1080 为基准设计**，`RenderContext.scale = width / 1920` 统一缩放到实际输出分辨率。写新控件时不要自己读 `cfg['width']`，一律乘 `self.s`。

## 3. 数据层 `scripts/telemetry.py`

### 3.1 配置加载与校验

- `config(path=None)`：读 `assets/default-config.json`，`merge()` 深合并用户配置覆盖。校验规则写在函数体里：
  - `1 ≤ fps ≤ 240`；`render_fps` 必须**整除** `fps`（HUD 低频绘制、FFmpeg 补帧到输出帧率）；
  - `alpha_codec ∈ {prores4444, qtrle}`；`padding_seconds.head/tail ≥ 0`；
  - 宽高必须为**正偶数且 16:9**（布局按 16:9 设计，改比例需重排 BottomBar）；
  - `speed_max_kmh / torque_max_nm / g_max / trail_seconds / max_gap_seconds > 0`；
  - 电机槽固定 FL/FR/RL/RR 四个；`g_ball_direction ∈ {-1, 1}`。

### 3.2 CSV 解析 `load_csv(path)`

AiM 导出 CSV 的结构是：若干行元数据（`Vehicle`、`Racer`、`Segment Times`、`Duration`…）→ 表头行 → 单位行 → 数据行。处理要点：

- 编码尝试顺序 `utf-8-sig → gb18030 → cp1252`（兼容 BOM 和中文环境导出）；
- **表头行不是第一行**：扫描所有首列规范化后等于 `time` 的行，取**非空单元格最多**的一行当表头（元数据行也会被逗号补齐到与表头等宽，如 E04 导出的 `Time,3:17 PM`+空列——按总宽选会误选元数据行，这是历史 bug）；
- 重复列名直接报错（不做静默去重）；
- 单位行 = 表头后第一行（首格转不成 float 即认定）；
- 全列 `to_numeric(errors='coerce')`，丢 `inf`，按 Time 排序，首列重命名为 `Time`；
- 返回 `(DataFrame, metadata dict, units dict)`。

### 3.3 列名模糊匹配 `resolve(spec, columns)` 与别名 `aliases`

`spec` 可以是字符串或候选列表。匹配两轮：

1. **精确轮**：`norm()`（小写、去掉所有非字母数字）相等即命中（`Acc-2` ↔ `Acc2` 就靠这层）；
2. **词序无关轮**（精确轮全部落空时）：分词后词集合相等即命中（`FL Motor Torque` ↔ `Motor Torque FL`，E04 与 A04 记录仪命名词序不同）。同词集多列 → 歧义报错。

候选列表按顺序尝试——这就是配置里 `["FL Motor Torque", "FL Torque"]` 的含义。
歧义（同一轮多个列命中）报错，找不到返回 `None`（多数通道缺失只是 warning，speed 缺失则硬报错——没有速度整个 HUD 没意义，且**不做 GPS 速度回退**）。

**aliases（通道别名）**：控件绑定名固定（如电池区读 `Battery Volt`），不同车辆的 CSV 列名不同时，在 config 里配 `"aliases": {"Battery Volt": "Bat Voltage"}`（值为列名或候选数组，空数组=显式不绑定）。`prepare()` 的 bound-channels 循环里：规范名精确匹配失败 → 查 aliases → 命中则以规范名存入 `data`（控件代码零改动）。桌面工作台的手动绑定下拉框生成的就是这份 aliases。

### 3.4 时间对齐 `alignment(sync)` 与 `seconds(value, fps)`

对齐公式：**`video_seconds = data_seconds × scale + offset_seconds`**。

- 0 个锚点：`scale=1, offset=sync.offset_seconds`；
- 1 个锚点 `{data_seconds, video_time}`：`scale=1, offset = video_t - data_t`；
- 2 个锚点：线性回归出 scale 和 offset（可修正录制时钟漂移，report 里给 `drift_ppm`）；
- `video_time` 支持 `HH:MM:SS:FF` / `HH:MM:SS.s` / 秒数；**drop-frame timecode（含 `;`）不支持**，直接抛错；
- 锚点与 `offset_seconds` 互斥。

### 3.5 核心：`prepare(path, c, start, duration)`

返回 `(data, query, report)`。`data` 是 `{键: np.ndarray(len=总帧数)}`，所有控件按帧号 `i` 取值。流程：

1. **帧轴构建**：输出帧数 = 头部 padding + 内容帧数 + 尾部 padding（`padding_seconds`，默认前后各 5s 空数据 HUD，UI 保留、数值显示 `--`）。
   `video_time[i] = start + i/fps`（输出/录像时间轴），`query[i] = (video_time_i - offset)/scale`（数据时间轴）。
2. **插值 `interpolate(name, kind)`**：同时间戳去重取均值 → `np.interp` 线性插值 → **空洞策略**：相邻采样点间隔 `> max_gap_seconds`（默认 0.5s）的区间内置 NaN（不猜数据）。超范围（前后 padding）也是 NaN。`kind` 决定单位换算（m/s→km/h ×3.6、mph、m/s²→g）并校验单位合法性（单位 `#` 是 AiM 的「未指定」标记，视为放行）。
3. **固定通道**：speed/throttle/brake/lat/lon/acc_x/acc_y（见 `names` 映射）。
4. **电机**：每槽 `active`（bool 或 `"auto"`——torque 列存在即启用）→ 生成 `FL Torque` 等数组；一条 torque 通道映射给多个电机直接报错。**功率 = Σ(扭矩 × RPM × 2π/60000)**，缺 RPM 则整机功率 NaN（不报部分值）。
5. **刹车归一化**：`Brake Relative = (Ave Brake - min) / (max - min) × 100`（本次记录内的相对百分比）；恒定值时显示 0 并 warning。
6. **布局绑定通道 `bound_channels(c)`**：遍历 layout 每个 spec，取 `spec.source` 或控件类 `DEFAULT_SOURCE`（**支持列表**），把这些 CSV 通道也插值到帧轴（`Battery Soc`、`Battery Volt`、`Battery Current`、`Steer Sense` 等就是这么进来的）。特例：`Steer Sense`/`Ave Steer` 缺失时不 warning（转向控件有降级链）。
7. **GPS 轨迹**：`Route Latitude/Longitude/Route Time`（原始采样，不插值，控件内部按 Time 查找）。
8. **report**：帧数/时长/分辨率/编解码/padding/通道映射表/电机激活表/brake_range/对齐公式/**meta（vehicle、racer、lap_seconds，从 CSV 元数据解析，`Segment Times` 如 `"1:17.000"` → 77.0）**/warnings。inspect 命令打印的就是它。

## 4. 渲染层 `scripts/widgets.py`（核心）

### 4.1 模块常量与工具

```python
CANVAS_W, CANVAS_H = 1920, 1080        # 设计基准分辨率
WHITE / GREEN / RED                     # 唯一三个语义色；一切透明度变化走 with_alpha/scale_color
```

- `with_alpha(color, alpha)`：直接指定 alpha（支持传 float，会被 `draw` 隐式取整）——注意 `with_alpha(WHITE, 60 * alpha)` 这种写法中 `alpha` 是控件 opacity，两套透明度相乘。
- `scale_color(color, factor)`：按比例缩放 alpha，用于"填充色跟随控件透明度"。
- `fmt(value, digits, dash="--")`：NaN → `"--"`，这是全 HUD 的缺失值显示约定。
- `fmt_clock(seconds)`：`m:ss.t`；无效/负数 → `"--:--.-"`。
- `draw_clock(dr, fonts, xy, text, size, fill, family="bold", anchor="mm"|"lm"|"rm")`：**Formula1 Display 字体的冒号字形是一个底部方点，形似句号**，所以 m:ss.d 里的冒号由两个方形点手工绘制（偏移 `cy - 0.20*size` 与 `cy + 0.15*size`，点径 `max(2, 0.09*size)`），其余字符照常。所有计时文本必须走这个函数，不要直接 `dr.text`。
- `Fonts`：按 (family, size) 懒加载缓存。`regular/bold = Formula1-Display-*`，`semibold = Titillium-SemiBold`（F1 Display 没有中间字重）。`fonts.text(..., shadow=True)` 默认加 1px 半透明黑描边保证在亮背景上可读。
- `speed_ticks()` 返回 `[0,30,60,90,120]`——**用户确认过的定稿，不要改**。

### 4.2 RenderContext —— 控件的唯一数据入口

```python
ctx.data          # prepare() 产出的 {键: ndarray}
ctx.cfg           # 合并后的完整配置
ctx.info          # {"vehicle","racer","lap_seconds"} 来自 CSV 元数据
ctx.fonts         # Fonts 单例
ctx.logo          # 纯白 logo PIL Image
ctx.scale (self.s)  # width/1920，所有 spec 坐标乘它
ctx.motor_slots   # 启用的电机槽列表；全禁用时回退为全部四个（显示空框 + --）
```

关键方法：

- `ctx.get(key, i)`：取第 i 帧，键不存在或越界返回 NaN。**控件里永远这么取数**。
- `ctx.route(w, h)`（带缓存）：把整条 GPS 轨迹等比投影进 w×h 局部坐标，居中、四周留 4px。缓存键是 `w`——**同宽不同高的两次调用会命中同一个错误缓存**，需要不同纵横比时改缓存键。
- `ctx.live_route_xy(i, w, h)`：当前帧车辆位置在局部坐标里的浮点坐标；按 `Data Time` 在 Route Time 里二分 + 线性插值，间隔超 `max_gap_seconds` 或数据缺失返回 None（红点消失而非乱跳）。

### 4.3 Widget 基类契约

一个控件 = 一份 spec。子类必须实现：

| 成员 | 说明 |
|---|---|
| `TYPE`（类属性） | spec 里的 `type` 字符串，注册进 `REGISTRY` 的键 |
| `DEFAULT_SOURCE`（类属性，可选） | 绑定的数据键，**str 或 list**。`bound_channels()` 会自动把这些通道插值好放进 `ctx.data` |
| `__init__(spec, ctx)` | 先 `super().__init__`（得到 `self.s / opacity / origin / x / y / card`），再解析自己的参数（都应提供合理默认值） |
| `size()` → (w, h) | 内容区尺寸。**基类坐标体系一律按 1920 基准写死数值再乘 `self.s`**（BottomBar/TimingBar 的做法）；小控件可以简化为不缩放（demo 遗产，输出 2K 时这些控件由整体 BICUBIC 放大兜底） |
| `paint_base(dr, ox, oy)` | **静态部分**：底色、刻度、标签、框线——不随帧变化。默认空实现 |
| `paint(dr, i, ox, oy)` | **动态部分**：随帧变化的数据。`ox, oy` 是内容区左上角 |

基类提供的：

- `place(w, h)`：按 `origin`（tl/tc/tr/ml/mr/bl/bc/br）+ `x/y` + 自身尺寸算出画布左上角。`x/y` 是**到对应边缘的距离**（tr 时 x 是到右缘的距离，以此类推）。
- `draw_card(dr, ox, oy, w, h)`：`spec.card = {"title": ...}` 时的半透明卡片底。卡片机制在 `_prepare_layout` 里实现：**卡片尺寸 = 内容尺寸 + 2×card_pad + 标题高**，内容原点相应内移——所以控件 `size()` 只管内容，不用管卡片。
- `content_origin(w, h)`：默认即 `place()`；卡片场景由 `_prepare_layout` 接管。

**静态/动态分离的意义**：`_prepare_layout(ctx, widgets)` 把所有 `paint_base` 画进一张缓存图层（键 = 控件对象 id 元组），每帧只需 `base.copy()` + 各控件 `paint()`。改控件时必须保持这个划分，否则性能退一个量级。**同一个几何量在 paint_base 和 paint 里各写了一份，改位置时两边必须同步改**（G 力圆心、转向圆心、扭矩框都是成对的）。

### 4.4 渲染管线函数（模块尾部）

### 4.6 BottomBarWidget —— v24 冻结布局详解

底部通栏，高 172px（1920 基准），贴满底边与左右两端。**所有几何常量都集中在这**：

```python
BASE_PAD = 15        # 统一留白：屏幕边缘/分割线 到内容的距离
BASE_DIVIDER_SHIFT = {"pedals": 10}   # 仅分割线位移（不改内容位置）：pedals 右缘线右移 10px
BASE_SECTIONS = [     # (区块名, x0, x1) @1920 基准
    ("gps", 0, 305), ("battery", 305, 600), ("steer", 600, 800),
    ("speed", 800, 1215), ("pedals", 1215, 1371), ("gforce", 1371, 1570),
    ("motors", 1570, 1920)]
```

结构约定（改布局前必读）：

- **区块索引是硬编码的**：`self.SECTIONS[0]=gps, [1]=battery, [2]=steer, [3]=speed, [4]=pedals, [5]=gforce, [6]=motors`。换区块顺序时必须同时改 `BASE_SECTIONS` 和 paint_base/paint 里所有 `SECTIONS[k]` 的 k——历史上在这翻过车（调换 pedals/gforce 后索引没跟上）。
- 分割线画在 `edge + BASE_DIVIDER_SHIFT[name]`，内容不受 shift 影响——**"只动分割线不动内容"的微调机制**。
- 内容区：`top = oy + 12s`，`ch = H - 12s - 20s`（底部 20s 留给标题行 `BATTERY/STEER/SPEED/G-FORCE/FL/FR/RL/RR/THR/BRK`）。
- 速度区：数字字号 80s、**预留 3 位数字宽**（`digit_w = textlength("0")` 实测而非估算），bar 起点 = `x0 + 12s + 3×digit_w + 10s`；刻度 0/30/60/90/120 均分。
- 转向环：半径 50s，底部缺口 `gap_deg=40°`，左正右负 ±max_deg(160)，绿弧 + 绿点 + 中心数字；**只读规范键 `Steer Sense`**（列名不同如 Ave Steer 由 aliases 在数据层映射，代码内不做降级——曾经的硬编码降级链会让「不绑定」失效），无数据显示 `"--"`。
- 扭矩区：零线固定 **3:1（正:负）**，正扭矩绿色向上（量程 `torque_pos_max=20`）、负扭矩红色向下（量程 `torque_neg_max=10`），超量程**封顶不溢出但数字如实显示**。
- 踏板区：**左 THR(绿) 右 BRK(红)**（v23 调换过，别改回去）；BRK 条右移 14s 与 THR 数字错位。
- G 力区：圆心 `x0 + P + 37s + 22s + r, top + 70s`（paint_base 与 paint 两处一致）；X 读数在盘上方居中，Y 列在盘左侧（"Y" 字与数字同 13s bold，Y 字在数字上方）；**G-FORCE 标题居中于左右分割线之间（含 pedals 的 divider shift）**。
- 电池区：SOC/VOLT/POWER/CURRENT 双行两列，列宽 116s、块宽 192s 居中；POWER 用的是 `Power`（总机械功率）。

spec 参数：`h, max_deg, positive_left, speed_max, torque_pos_max, torque_neg_max, map_w(285), map_h(158), gap_deg(40), opacity`。

### 4.7 TimingBarWidget（右上计时条）

370×60 卡片：左段 `TIME` 小标 + `draw_clock` 大号当前时间（37px，**字号是确认过的，别加大——之前误判"字太小"实为高度不够**）；竖线分隔；右段两行 vehicle（较亮）/ racer（较暗），右对齐。当前圈时间 = `Data Time` 对 `lap_seconds` 取模（等分段假设；真实信标圈计时是 TODO）。

## 5. 装配层 `scripts/hud.py`

很薄：`make_renderer(data, ts, cfg, info=None)` → 构造 `RenderContext` → `build_layout(cfg['layout'] or DEFAULT_LAYOUT)` → 返回 `frame(i)` 闭包。闭包内：渲染 1920×1080 RGBA，若 `cfg` 尺寸不同则 **BICUBIC** 缩放到输出分辨率（HUD 是线稿+文字，BICUBIC 边缘干净且比 LANCZOS 便宜；输出 2K 时全 HUD 靠这一步放大）。

`g_ball_offset(ax, ay, cfg, radius)` 是独立工具（测试在用）：反向惯性映射，加速球向后、刹车向前，左转向右。

`DEFAULT_LAYOUT` 硬编码了 v24 三个控件，与 `assets/default-config.json` 的 `layout` 键一致——**改布局两处都要改**（config 优先）。

## 6. 编排层 `scripts/dashboard.py`

CLI 四个子命令：

```
python dashboard.py inspect  <csv> [--config x] [--start s] [--duration d] [--output report.json]
python dashboard.py render   <csv> --output <dir> [--config x] [--start s] [--duration d] [--preview-only]
python dashboard.py verify   <mov> [--report report.json]
python dashboard.py init-config <output.json>          # 导出带默认值的完整配置
```

`render` 流程：`config → prepare → 写 resolved-config.json/report.json → 用峰值速度帧存 transparent.png + preview.jpg → 生成 25fps 8s 灰底 preview.mp4 → render_mp 并行渲染 → verify → 临时文件改名 dashboard_100fps_alpha.mov → 写 verification.json / progress.json / 使用说明.txt`。

细节：

- **编码输入是 rawvideo rgba 管道**。`-pixel_format` 必须与帧实际格式一致（rgba vs rgb24 差一个字节都全花屏），`-video_size` 必须与实际分辨率一致——这两个 mismatch 是之前"画面闪烁/三连平铺"两个 bug 的根因，改编码代码时先核对。
- HUD 按 `render_fps`（默认 20）采样渲染，FFmpeg `-vf fps=100` 补帧到输出帧率——HUD 变化平滑度够用且省 5 倍渲染量。
- alpha 编码二选一：`qtrle`（`-pix_fmt argb`，体积大但编码快，**当前默认**）；`prores4444`（`yuva444p10le`，体积/兼容性更好，交付推荐）。**不要用 libvpx-vp9**：本环境的 ffmpeg 写得出 ALPHA_MODE 元数据但 alpha 平面实际丢失（已用合成数据验证）。
- `verify()` 不依赖解码器返回值，直接**解析 MOV atom 树找 stsz 拿真实帧数**，再用 report 校验帧数/分辨率/帧率，并抽 3 个时间点解码检查：padding 帧必须全透明（max_alpha==0）、内容帧中心必须透明且全图必须有 255 的 alpha（确实是带透明内容的 overlay）。
- 输出目录里已有成品 MOV 时直接拒绝（防覆盖），分段产物叫 `dashboard.partial.mov`。

## 7. 并行渲染 `scripts/render_mp.py`

`render_chunks_parallel(data, ts, cfg, info, indices, out_mov, workers, progress_callback)`：

1. 把渲染帧号序列均分成 `workers` 段；
2. **multiprocessing spawn** 起独立进程，每个进程自己构建 `make_renderer` + 自己的 FFmpeg 实例，rawvideo 直写分段 MOV（无跨进程管道，`render_fps` 输入、`-vf fps` 补帧、`-frames:v` 精确控制每段输出帧数，末段对齐总帧数）；
3. 主进程从 Queue 收进度（每 15 帧一报），回调 `progress_callback`（dashboard 拿它写 progress.json；**接口已预留 `cancel_check` 参数**，接 GUI 取消用）;
4. 全部成功后 `concat demuxer + -c copy` 无损拼接；finally 里杀活进程、删 `_tmp_chunks_*` 临时目录。

**坑**：data/ts/cfg 通过 pickle 传给子进程，数组都是全量拷贝——数据量大时启动成本主要在这；`make_renderer` 的布局缓存在每个子进程里各自重建一次（`_prepare_layout` 的首次 paint_base），开销可接受。Windows 下必须 spawn，入口要 `if __name__ == '__main__'` 保护（dashboard 已满足）。

## 7.5 桌面工作台 `scripts/app_gui.py`（PySide6）

导出 GUI：拖 CSV → 左侧**通道绑定面板** → 右侧预览/导出。要点：

- **绑定槽位**集中在模块级 `BIND_SLOTS`（19 个：speed/throttle/brake/acc×2/gps×2/steer/battery×3/电机×8），每项 `(id, 显示名, 分组, 默认候选, 路由)`；路由三种：`channel`（直连 `cfg.channels`）、`alias`（生成 `cfg.aliases`）、`motor`（`cfg.motors[槽][字段]`）。**电机候选直接取 `telemetry.config()` 的默认配置**（RL/RR 含 L/R 别名），保持单一事实来源。
- **自动匹配**：导入 CSV 时对每个槽位跑 `telemetry.resolve(候选, 列)`，命中填入、未命中标红（17/19 命中是 E04 的实际水平，未命中 = 需要人来拍板的语义问题）。
- **手动绑定持久化**：项目根 `bindings.json` 按 CSV 文件名存全部槽位选择；载入时自动回放（保存值不在当前列中则忽略）。
- **`_collect_bindings()`** 把面板状态汇总成完整 `{channels, motors, aliases}` 覆盖项（channels/motors 是完整深拷贝+覆写，浅 `cfg.update` 即可生效）；「（不绑定）」= `channels[key]=None` / `aliases[key]=[]` / `motors[field]=None`（显式失活）。
- **`PreviewWorker`**：后台线程 prepare + 峰值速度帧整帧 + 底栏放大（crop 高 `172×scale`）两张 QImage + report warnings；`RenderWorker` 导出时接受同一份覆盖项。
- 线程注意：QImage 可跨线程，QPixmap 必须在 GUI 线程 `QPixmap.fromImage`；Qt 对纯 Python 槽函数持**弱引用**，连接后必须自己持引用（否则信号静默失效）。

## 10. 已知坑清单（历史事故，别再踩）

1. **Formula1 Display 冒号字形**像句点 → 所有 m:ss.d 走 `draw_clock()`。
2. **libvpx-vp9 alpha 不可用**（本环境 ffmpeg 丢 alpha 平面）→ 只有 QTRLE / ProRes4444 两条路。
3. **rawvideo 管道的 `-pixel_format` / `-video_size` 必须与帧实际值一致**，否则花屏/平铺（历史上表现为"闪烁"和"画面横向重复三遍"）。
4. **补丁脚本按类名切片改代码时会产生重复类定义**，Python 后定义覆盖先定义，渲染用的是旧类而 UI 显示新参数。每次改完 `grep -c "^class " widgets.py` 确认每个类恰好 1 次。整文件拷贝副本是治本方案。
5. **BottomBar 的 SECTIONS 索引与 paint_base/paint 成对硬编码**：换区块顺序两边都要改；几何常量（圆心等）在静态/动态两处各写一份，必须同步。
6. **测试固定 `c['fps']=100`**：默认 fps 是产品决策，测试不跟随默认值漂移——改默认 fps 不该改坏测试，也不该靠改测试迁就默认值。
7. **`ctx.route()` 缓存键只含宽度**：同宽不同高会命中错误缓存。
8. **用户已确认、不要"顺手优化"的定稿项**：Steer Sense 优先（"Steer Sense 就是角度"）、速度刻度 [0,30,60,90,120]、fps=100/render_fps=20、2K、QTRLE、底部 172 高、pad=15、pedals divider shift=10、THR 左 BRK 右。改动前先问。
9. Windows 注意：Python 脚本里别用 `/tmp`；cmd 批处理只能 ASCII+CRLF。
10. 输出目录已有成品 MOV 会拒绝渲染（防覆盖设计，不是 bug）。

## 11. 常见二次开发任务 How-To

### 11.1 新增一个控件

1. 在 `ui-demos/widgets.py` 写类：

```python
class LapDeltaWidget(Widget):
    TYPE = "lap_delta"
    DEFAULT_SOURCE = ["Lap Delta"]          # 需要的 CSV 通道（自动插值；没有则运行时 warning + 显示 --）

    def __init__(self, spec, ctx):
        super().__init__(spec, ctx)
        self.width = int(round(float(spec.get("w", 120)) * self.s))
        self.height = int(round(float(spec.get("h", 40)) * self.s))

    def size(self):
        return self.width, self.height

    def paint_base(self, dr, ox, oy):        # 静态：底卡/刻度/标签
        ...

    def paint(self, dr, i, ox, oy):          # 动态：每帧
        v = self.ctx.get("Lap Delta", i)
        self.ctx.fonts.text(dr, (ox, oy), fmt(v, 2), int(round(20 * self.s)),
                            WHITE, "bold", anchor="la")
```

2. 注册：`REGISTRY` 元组里加 `LapDeltaWidget`。
3. 在布局 JSON（config 的 `layout.widgets`）加 `{"type": "lap_delta", "x": ..., "y": ..., "origin": ...}`。
4. 数据通道：CSV 里有就直接用（`bound_channels` 自动插值）；CSV 没有而需由现有通道推导 → 去 `telemetry.py` 的 `prepare()` 里加（参照 `Brake Relative` 的写法），不要在控件里做非平凡运算。
5. ui-demos 跑 demo 验收 → 整文件拷回 `scripts/widgets.py` → 更新 `references/configuration.md` 与 `docs/UI优化与扩展设计.md`。

### 11.2 微调 BottomBar

- **只动分割线**：`BASE_DIVIDER_SHIFT` 加 `{"区块名": px}`（正值右移）。
- **动整块内容**：改 `BASE_SECTIONS` 的边界 → **同时**检查 paint_base/paint 里该区块的 `SECTIONS[k]` 索引是否还对、区块内部相对位置是否需要重排。
- **统一留白**：`BASE_PAD`。
- 任何微调后在 ui-demos 渲染静态帧 + 视频各验一遍（历史上出现过只看静态图漏掉动态错位）。

### 11.3 换输出规格

改 `default-config.json`（或用户 config）即可：`width/height`（16:9 偶数）、`fps/render_fps`（整除）、`alpha_codec`。布局全自动缩放。**改比例（非 16:9）不行**——BottomBar 通栏和 place() 都假设 16:9，校验层会直接拒绝。

### 11.4 新车/新赛道 CSV 适配

**首选：桌面工作台（`python scripts/app_gui.py` 或根目录 `启动桌面工作台.bat`）**。拖入 CSV 后左侧绑定面板自动匹配（候选=默认配置的 channels/motors/steer/battery 候选 + aliases），红字槽位手动下拉选择（按 CSV 文件名持久化到项目根 `bindings.json`，下次载入自动回放），右侧实时预览确认，然后直接导出。工作台在渲染时把面板状态汇总成 `{channels, motors, aliases}` 覆盖项传给 `RenderWorker`。

纯配置方式：把新 CSV 的列名加进 config 的 `channels.*` / `motors.*` 候选列表（`resolve` 按序尝试），控件绑定名不同的（电池等）配 `aliases`；单元不标准时在 `interpolate` 的单位表里加映射。用 `inspect` 先看 report 的 `channels/motors/warnings` 确认全部命中。注意**各车的数据语义要先问车队**（如 E04 的刹车是四轮独立油压、无 SOC 通道、转向角无符号——这些是车的问题，不是管线的问题）。

### 11.5 与自研软件（SCUTRacingTelemetry）集成

见 `docs/集成预研-与SCUTRacingTelemetry软件集成.md`。要点：Tauri 侧新增 `export_series` 命令导出全精度数据 → Python sidecar（PyInstaller onedir + 静态 ffmpeg）调用本管线 → M1 先做 10s 端到端透明 MOV。本代码库为集成预留的口子：`prepare()` 可作为纯库调用（不依赖 CLI）、`render_mp.render_chunks_parallel` 有 `cancel_check` 参数、所有输出产物为 JSON（report/verification/progress）。
